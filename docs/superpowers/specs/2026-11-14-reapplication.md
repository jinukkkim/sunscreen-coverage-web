# 재도포 기록·알림·하루 타임라인

검토일: 2026-11-14. 사용자 담당 범위 3·4·5를 구현한다. 사용자는 우선 페이지를 열어 둔 상태의 알림을 선택했다.

## 요구사항 검증과 적용

| 요청 | 적용 기준 |
| --- | --- |
| 재도포 알림 | 야외활동 시 실제 직전 도포 + 2시간. 매일 직접 켜며 종료 시각까지. 기기 알림이 없어도 화면 알림 표시 |
| 직전 도포 기록 | 지금/오늘 이전 시각 직접 입력. 한국 시간. 미래·같은 분 중복 방지, 잘못 입력한 기록 취소 |
| 하루 타임라인 | 완료 기록과 조건부 2시간 계획을 구분. 실제로 바르면 그 시각부터 다시 계획. 지난 예정을 자동 완료하지 않음 |
| UV 예보 반영 | 기상청 발표 시각과 3시간 구간 값을 각 일정에 매칭. 개인별 도포 지속 시간 또는 차단력으로 환산하지 않음 |
| 알림 때 위치 갱신 | 명시적 동의 후 매번 maximumAge=0, timeout=8초로 새 위치 요청. 실패해도 알림 유지. 위치·예보는 저장하지 않음 |

## 근거와 판단

- [미국피부과학회 사용 안내](https://www.aad.org/public/everyday-care/sun-protection/shade-clothing-sunscreen/how-to-apply-sunscreen): 야외에서 약 2시간마다 재도포, 수영·땀 후 바로 재도포. 사용 제품 표시를 우선 확인하도록 안내한다. 이 기준을 UV만으로 자동 연장/단축하거나 SPF × 시간으로 바꾸지 않는다.
- [기상청 생활기상지수 조회서비스(4.0)](https://www.data.go.kr/data/15085288/openapi.do): 발표 시각 기준 3시간 단위, 최대 75시간 후 예측값. 앱 자체 예측 모델을 만들지 않고 공식 구간 예보를 사용한다. 0은 유효한 값, 빈값·음수·오래된 발표는 데이터 없음으로 처리한다.
- [MDN 위치 API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition): HTTPS/localhost, 사용자 허용이 필요하며 maximumAge=0은 캐시 좌표 대신 새 위치를 요청한다. GPS 정확도나 시간 내 성공을 보장하지 않는다.
- [MDN 브라우저 알림](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API): 권한은 버튼 클릭에서 요청한다. 모바일의 Notification 생성자 제약을 고려해 서비스 워커의 showNotification을 우선 사용한다.

## 상태와 동작

`sunguard.care.v1`: version, records[{id, at}], enabled, activeDay, endTime, delivered[id]. 실제 기록은 최근 30일분만 읽고 페이지 진입/저장 시 정리한다. 활성 알림은 해당 한국 날짜에만 유효하다. 도포 시각이 자정을 넘는 계획은 다음 날로 자동 승계하지 않는다.

예: 09:00 도포 → 다음 11:00. 10:30에 실제 재도포 → 다음 12:30. 11:00에 바르지 않았으면 11:00 계획이 지났음을 표시하며 실제 기록은 09:00 그대로다. 그 뒤 계획은 앞선 예정대로 발랐을 때의 조건부 계획이다. 알림을 확인하는 것만으로 재도포를 기록하지 않는다.

화면이 보일 때 10초 간격과 focus/visibilitychange에서 검사한다. 절전·잠금·백그라운드 시 정확한 예약 실행은 보장하지 않는다. 복귀 시 종료 시각 안이면 미전달 알림을 한 번 표시한다. 동일 도포 기록에는 한 번만 알리며 전달 식별자를 저장한다. 지원 브라우저에서는 Web Locks로 여러 탭의 중복 전송을 막는다. Web Locks 또는 저장소 사용이 제한된 환경에서는 여러 탭 동시 실행의 중복 방지가 보장되지 않는다.

알림을 화면에 먼저 표시하고 새 위치·예보 결과를 추가한다. 기기 알림은 갱신 결과 또는 실패 안내를 포함한다. 갱신 중 새 도포를 기록하거나 알림을 끄면 지난 기기 알림을 보내지 않는다. 기기 알림과 위치 갱신 선택은 이번 페이지 세션에만 적용하며 새로고침 후 다시 선택한다.

예보는 조회 후 1시간이 지나면 오래된 것으로 보고 화면 수치 대신 확인 필요 상태를 표시한다. 구간 밖 시간은 보간하거나 가상 값으로 채우지 않는다.

## 데이터 흐름

카메라 영상은 브라우저 미리보기에서만 사용한다. 영상·사진·도포 기록은 외부 전송하지 않는다. 도포 기록/알림 식별자/일정 설정은 브라우저 localStorage에 저장한다. 위치와 예보는 메모리에서만 사용하고, 위치 동의는 세션 범위로 취소할 수 있다.

사용자가 위치 갱신에 동의하면 장치 좌표를 소수 셋째 자리로 반올림해 앱 서버에 전송한다. 이는 완전한 익명화가 아니며 대략적인 위치 정보다. 서버는 공식 지점표에서 50km 안의 가장 가까운 지점을 찾고, 기상청에는 지점 코드와 발표 시각·서버 인증키만 전송한다. 행정구역 경계 판정이 아니므로 지점명과 거리를 함께 표시한다. 앱 서버는 요청 좌표를 저장/로그하지 않는다. 운영 프록시·호스팅의 URL 로그는 별도로 좌표 쿼리를 제거해야 한다.

기상청 응답은 지점/발표 단위 최대 256개, 10분 캐시한다. 동시 요청은 합치고 오류 원문이나 키를 사용자에게 노출하지 않는다. 키 미설정은 503으로 명시하고 가짜 예보로 대체하지 않는다.

## 검증

`npm test`: 시각 기록·재도포 재계산·한국 날짜 경계·종료/옵트인·복원/중복 방지·UV 빈값과 구간/캐시·위치 실패·기기 알림 실패·진행 중 취소·API 상태를 검사한다. 모의 예보는 테스트 파일에만 둔다.

`npm run build` 후 `npm run test:e2e`: 설치된 Chrome에서 직접 기록, 새로고침 복원, 미래 입력 거부, 알림마다 새 위치 호출, 위치 거부 시 알림 유지, 모바일 가로 넘침을 검사한다. 기기 시간은 테스트 안에서만 고정한다.

2026-11-14 기존 로컬 설정의 승인된 키로 서울 지점 실서비스 조회에 성공했다. 15시(KST) 발표분의 유효 구간 19개를 반환했다. 키나 사용자 좌표를 테스트 산출물에 저장하지 않았다. 실제 기기별 권한 UI, 절전·잠금 동작, 모바일 OS 알림 표시는 별도 확인이 필요하다.
