# 얼굴 스캔 후 부위별 도포 동작 인식

- 작성일: 2026-11-14
- 상태: 동작 베이스라인 구현 및 자동·브라우저 검증. 실제 사람의 인식 정확도는 미검증
- 사용자 요구: 선크림 도포 인식이 메인 기능. 처음에 이마·코·볼 등의 부위를 확인해 인식 정확도를 높이는 방향을 고려한다. 지원 목표는 모든 선크림이다.
- 사용자가 제시한 첫 접근: 선크림을 바르는 모션을 인식하는 naive한 방법.
- 설계 제안: 얼굴 부위를 먼저 확인하고 계속 추적한 뒤, 부위별 문지르는 동작을 감지하는 베이스라인부터 구현한다. 아래 구역 수와 동작 조건은 구현 담당자의 제안이며 아직 사용자가 승인한 세부사항은 아니다.
- 사용자 확인: 제품 제한 없이 손으로 펴 바르는 동작부터 구현한다. 스틱·쿠션·분사 자체의 동작 인식은 첫 버전에 포함하지 않는다. 해당 제품을 손으로 펴 바르는 동작은 제품 종류로 제외하지 않는다.

## 목적과 판단 범위

사용자가 얼굴의 어느 부위에서 바르는 동작을 수행했는지 확인하도록 돕는다. 제품의 색·백탁·광택을 입력 조건으로 삼지 않아 특정 제품을 선택하거나 등록하지 않고 사용할 수 있도록 한다.

**모든 제품에서 동작 안내를 사용할 수 있다는 것과 모든 제품의 실제 도포를 검출한다는 것은 다르다.** 첫 버전은 도포 동작의 관찰 결과다. 손의 이동만으로 실제 선크림 전달·접촉·양·누락 면적·SPF·UVA 보호를 확정하지 않는다. 실제 도포 인식이라는 최종 목표는 유지하고, 동작 기반 결과를 비교 기준으로 삼는다.

얼굴 스캔의 정확도 개선 효과도 아직 측정하지 않았다. 스캔은 개인별 얼굴 좌표와 분석 구역을 정하는 초기화 단계이며, 스캔 이후에도 매번 현재 얼굴 위치를 추적해야 한다. 얼굴 본인 인증이나 의료용 3D 스캔을 구현하는 것은 아니다.

## 현재 코드와 변경 범위

- React/Vite 스켈레톤, 카메라 미리보기·권한 오류·종료 처리는 존재한다.
- 얼굴·손 모델, 분석 루프, 인식 결과는 없다. 학습 데이터셋도 확보되지 않았다.
- `src/lib/camera.js`의 스트림 소유권과 취소 처리를 유지한다.
- `src/components/Camera.jsx`에 모델 준비·스캔·추적의 시작/종료와 영상 오버레이를 연결한다.
- `src/App.jsx`의 빈 결과를 실제 관찰 상태로 바꾼다. 보조 기능은 이번 범위에 포함하지 않는다.
- 영상 처리·구역 계산·동작 누적 계산을 UI와 분리해 기존 Node 테스트에서 검증한다. 파일 수와 세부 함수 구성은 계획 단계에서 정한다.

## 사용자 흐름

```text
카메라 켜기 / 모델 준비
  → 얼굴을 정면 안내선에 맞추기
  → 얼굴 1개와 구역 위치가 안정되면 구역 표시
  → 사용자가 '부위 확인 후 시작' 선택
  → 부위별 문지르는 동작 추적
  → 관찰된 부위와 아직 관찰되지 않은 부위 표시
```

### 1. 얼굴 스캔

- MediaPipe Face Landmarker로 얼굴 윤곽과 특징점을 추적한다.
- 첫 범위는 정면에서 관찰 가능한 이마·코·사용자 기준 왼쪽 볼·오른쪽 볼·턱의 5구역이다.
- 구역은 얼굴 특징점 기반 다각형으로 정의한다. 눈·입 내부와 얼굴 바깥을 분석에서 제외한다. 구역 경계는 중복 누적되지 않게 한다.
- 눈가·귀·목·머리카락에 가려진 이마 등은 이 버전의 관찰 범위 밖임을 명시한다. 5구역 결과를 얼굴 전체 도포 완료로 표시하지 않는다. 모든 선크림 지원과 관찰 부위 범위는 별개다.
- 얼굴 부위는 대략적인 추정 영역이다. 얼굴 모델만으로 머리카락·수염·손 가림이 정확히 분할된다고 가정하지 않는다. 사용자가 오버레이를 확인하고 가려진 부위를 정리하도록 안내한다.
- 얼굴 없음·복수 얼굴·과도한 기울임·프레임 밖 얼굴·불안정한 좌표에서는 시작을 허용하지 않고 이유를 보여준다. 가능한 경우 복수 얼굴을 검출하도록 설정하고 임의로 한 사람을 선택하지 않는다.
- 스캔 결과는 최초 기준만 제공한다. 추적 중에도 구역 위치를 현재 얼굴에 맞춰 갱신한다.

### 2. 동작 인식

- 동일한 MediaPipe Tasks Vision 패키지의 Hand Landmarker로 손 특징점을 얻는다.
- 손가락 끝과 관절의 좌표를 얼굴 좌표계로 정규화한다. 원본 화면에서 머리가 움직였다는 이유만으로 문지르기 이동량이 늘어나지 않도록 한다.
- 선택된 손가락 끝 여러 점이 한 구역 안이나 가까이에 있고, 같은 구역에서 일정 시간 움직이며 충분한 이동 범위를 보이면 동작 후보로 누적한다.
- 정지한 손, 잠깐 통과한 손, 다른 구역에 있는 손, 얼굴만 움직이는 경우를 별도 음성 조건으로 검증한다. 단순히 구역에 3초 머물렀다는 이유만으로 감지하지 않는다.
- 첫 실험의 시간 기준은 2초의 유효 움직임을 제안한다. 좌표 흔들림을 제외할 이동 범위·연속성·허용 간격은 얼굴 크기로 정규화한 코드 상수로 두고 실기기에서 조정한다. 이 값들은 정확도 검증 결과가 아니다.
- 프레임 수 대신 실제 시간 차이를 사용한다. 긴 프레임 공백을 누적 시간으로 계산하지 않는다.
- 한 손의 같은 시점 관측을 여러 구역에 중복 적립하지 않는다. 경계에서는 가장 가까운 한 구역으로 지정하거나 모호하면 누적하지 않는다.
- 모델 결과 배열의 순서를 손의 영구 식별자로 쓰지 않는다. 손 대응이 모호하거나 손이 사라지면 해당 연속 동작 후보를 초기화한다. 두 손의 시간을 합산해 기준 시간을 단축하지 않는다.
- 감지된 부위는 세션 동안 유지한다. 사용자가 '다시 시작'을 누르면 모두 초기화한다.
- **얼굴 앞의 공중 문지르기는 이 방식으로 실제 접촉과 확실히 구분할 수 없다.** 얼굴 모델과 손 모델의 z 값을 그대로 비교해 접촉 거리로 해석하지 않는다. 공중 동작의 오탐을 측정하고 결과의 한계로 남긴다.

### 3. 결과와 중단

부위 상태는 `대기 → 동작 관찰 중 → 도포 동작 감지`로 표시한다. 품질이 나쁜 프레임에서는 `추적 불안정 / 다시 정면을 봐 주세요` 등의 안내를 우선한다.

```text
부위별 도포 동작
이마        도포 동작 감지
코          동작 관찰 중
왼쪽 볼     아직 감지되지 않음
오른쪽 볼   아직 감지되지 않음
턱          아직 감지되지 않음

관찰 범위: 정면 5구역 · 실제 도포량/차단력은 측정하지 않음
```

- 카운트가 필요하면 `5구역 중 2구역에서 동작 감지`로 표시한다. `도포율 40%`, `보호 완료`, `미도포 확정`으로 바꾸지 않는다.
- 다섯 구역을 채워도 문구는 `관찰 대상 5구역에서 동작을 감지했습니다`다.
- 얼굴을 잃거나 복수 얼굴이 보이면 누적을 멈추고, 다른 사람이 결과를 이어받지 않도록 재스캔 시 기존 세션의 결과를 초기화한다. 얼굴 본인 인증은 하지 않는다.
- 모델 추론 중 실패하면 부분 결과를 완료로 바꾸지 않는다. 분석 실패를 알리고 재시도할 수 있게 한다. 카메라는 사용자가 끌 수 있어야 한다.

## 실행·수명·데이터

- 추론은 브라우저 내부에서 한다. 영상·프레임·특징점은 서버에 전송하거나 파일로 자동 저장하지 않는다. 세션 종료 시 메모리 참조도 해제한다.
- 패키지·WASM·모델 버전을 고정하고 모델 및 실행 자산은 앱과 같은 출처에서 제공하는 구성을 우선한다. 자산의 실제 라이선스와 재배포 조건을 구현 때 확인해 고지한다. 프로젝트의 MIT 저작권은 SunGuard contributors를 유지한다.
- 모델 다운로드와 카메라 영상 업로드는 구분한다. 외부 자산 호스트를 사용하게 되면 해당 요청과 영상 미전송 사실을 README에 기록한다. 외부 분석 API는 이번 설계에 없다.
- 카메라와 모델 준비 상태를 각각 표시한다. 모델 로딩 실패는 재시도 가능해야 하고 영상 미리보기까지 고장내면 안 된다.
- 중복 분석 루프와 추론을 만들지 않는다. 동일 영상 프레임 재처리와 겹치는 추론을 막고 처리 빈도를 제한한다. 우선 현재 구조에 맞춰 구현하고, 실제 지연이 확인되면 Worker를 검토한다.
- 숨겨진 탭에서는 동작 누적을 멈춘다. 복귀 후 대기 시간을 동작 시간으로 계산하지 않는다.
- 끄기·컴포넌트 해제·재시도 시 프레임 콜백과 모델 자원을 정리한다. 늦게 끝난 모델 로딩 결과나 추론이 새 세션에 반영되지 않도록 취소 토큰을 사용한다.
- 원본 영상 좌표, `object-fit: cover` 크롭, 거울 반전과 오버레이를 같은 변환으로 처리한다. 왼쪽·오른쪽은 사용자 기준으로 일관되게 표시한다.

## 검증과 완료 기준

### 자동 검증

1. 얼굴 크기·위치·회전이 변해도 구역 및 정규화된 손 위치가 함께 움직이는지 확인한다.
2. 구역 밖·경계·눈과 입 제외 영역·비정상 좌표를 다룬다.
3. 손 정지, 짧은 통과, 얼굴만 움직임, 지속적인 문지름, 프레임 간격 변화, 손 검출 순서 변화, 추적 손실을 재현 가능한 합성 특징점으로 검사한다.
4. 오래된 콜백·긴 공백·분석 중단이 진행 상태를 갱신하지 않는지 확인한다. 기존 카메라 종료·취소 테스트를 유지한다.
5. `npm test`, `npm run build`를 실행한다. 합성 테스트 통과를 실제 사람 인식 정확도라고 부르지 않는다.

### 실제 기기 검증

- 정면 각 구역 문지르기, 두 손 사용, 정지한 손, 얼굴 앞 공중 문지르기, 손 통과, 고개만 움직이기, 손/머리카락 가림, 조명 변경을 구분해서 기록한다.
- 동작 없이 선크림이 이미 발린 경우와 선크림 없이 문지르는 경우도 검사한다. 이 버전이 실제 제품 존재를 판단하지 못한다는 사실을 결과에서 확인한다.
- 휴대폰과 노트북에서 권한·모델 로딩·좌우 표시·처리 지연·종료 후 카메라 해제·화면 이탈을 확인한다.
- 원본 참가자 사진·영상과 생체 특징점은 저장소에 넣지 않는다. 수동 실험은 동의한 참가자와 진행하고, 우선 비식별 조건·관찰 결과·모델 버전만 기록한다. 원본 수집이 필요하면 수집 전 동의·보관·삭제 방식을 별도로 정한다.
- 동작 감지 성공/실패·오탐·추적 실패·감지 지연을 따로 기록한다. 얼굴 부위가 고정된 화면 구역을 쓸 때와 비교해 초기 스캔 및 지속 추적의 효과를 평가한다. 실험 전 결과 수치나 정확도 목표를 임의로 공표하지 않는다.

첫 구현의 완료는 5구역 스캔, 부위별 동작 감지, 보류·초기화·자원 정리, 자동 테스트와 빌드 통과를 의미한다. 실제 기기 확인을 수행하지 못했다면 그 항목을 미확인으로 남긴다. 이것을 실제 도포 인식 완료로 보고하지 않는다.

## 실제 도포 인식으로 발전시키는 조건

- 제품군을 임의로 한두 개로 제한하지 않는다. 유기·무기·혼합·틴티드·투명 제형, 바른 직후/마른 뒤, 무도포·보습제·물기·피지 등의 대조 조건을 실험에 포함한다.
- 동작 정답과 실제 도포 영역 정답을 분리한다. 제품의 알려진 도포 위치를 기록하고, UV 등 참조 장비를 쓰는 경우도 해당 제품의 대비 유효성을 확인한다.
- 인물·제품·촬영 회차가 평가에 누출되지 않게 나눈다. 보지 못한 제품에서도 누락 부위를 찾는지 별도 평가한다.
- 얼굴 정렬과 RGB 전후 비교는 추가 관찰 신호의 후보일 뿐이다. 동작 기반 기준보다 실제 누락 검출이 개선되는지 비교한 뒤 채택한다.
- 기본 RGB에서 실제 도포와 대조 조건을 구별할 근거가 부족하면 판정 불가로 남긴다. 이때 모델을 더 크게 만드는 것만으로 모든 제품 지원이 해결된다고 약속하지 않고, 추가 입력·센서 또는 요구 조건을 다시 검토한다.

## 근거와 확인 한계

2026-11-14 공식 문서와 연구를 확인했다. 아래는 라이브러리 기능 및 연구 결과이며 SunGuard의 성능 시험 결과가 아니다.

- [MediaPipe Face Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker?tab=Web): 브라우저에서 얼굴 특징점·변환 행렬을 얻는 API. 선크림 검출 모델이 아니다.
- [MediaPipe Hand Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker?tab=Web): 동일 패키지에서 손 특징점을 얻는 API. 얼굴과의 접촉 판정 API가 아니다.
- [Face Mesh V2 model card](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Face%20Mesh%20V2.pdf): 얼굴 추적의 입력 조건·조명·가림·각도에 따른 한계. 본인 식별 모델이 아니다.
- [선크림 외관 색 정량화 연구](https://pubmed.ncbi.nlm.nih.gov/29080360/): 표준화된 사진에서 제품·양에 따라 외관 차이가 달라짐. 실제 차단력이나 모든 제품 도포 검출의 근거가 아니다.
- [UV photography 연구](https://derma.jmir.org/2021/1/e24653/): 추가 UV 장비와 제품별 관찰 한계. RGB 검출 또는 UV의 보편적 정답을 입증하지 않는다.

## 구현 전 확인할 결정

첫 버전은 **제품 제한 없이 손으로 펴 바르는 도포 동작**으로 사용자에게 확인받았다. 얼굴 정면 5구역의 베이스라인으로 설계하고 시간·이동 임계값과 세부 UI 배치는 구현자가 보수적으로 정해 실기기로 조정한다. 실제 선크림 존재를 검출하는 기능은 후속 검증 과제로 명확히 남긴다.

이 접근이 가능한 모든 방법 중 최선이라고 입증된 것은 아니다. 현재 데이터·장비가 없는 웹 프로젝트에서 제품 외관에 의존하지 않고 실험을 시작할 현실적인 기준으로 선택한다. 학습한 동작 분류기와 RGB 외관 비교는 각각 이 기준보다 동작 오탐 또는 실제 누락 검출이 개선되는지 평가한 뒤 추가한다. 모션 인식 성능을 높여도 제품 존재를 입증하지는 못한다.
