# SunGuard

2026 서울시립대학교 해커톤 팀이 진행하는 선크림 도포 인식 웹 프로젝트입니다.

선크림을 바를 때 빠뜨린 부위를 알아차리고 보완하도록 돕는 것을 목표로 합니다. 현재는 기획·기술 검증 단계이며, 기본 카메라를 이용한 실제 도포 인식 정확도는 아직 검증되지 않았습니다.

팀이 함께 작성·검토하는 프로젝트이며, MIT 라이선스로 공개합니다.

## 개발 시작

Node.js 22.13 이상을 사용합니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 localhost 주소를 브라우저에서 여세요. 기본값은 `http://localhost:5173`이며 Express가 앱과 API를 함께 제공합니다. 휴대폰 카메라·위치·기기 알림에는 HTTPS 주소가 필요합니다.

```sh
npm test
npm run build
npm start
npm run test:e2e
```

브라우저 테스트는 설치된 Chrome을 사용합니다. Chrome이 없는 환경은 `npx playwright install chromium` 후 `playwright.config.js`의 `channel`을 제거하세요. `npm run preview`는 정적 화면 확인 전용이므로 UV API는 제공하지 않습니다.

## 현재 구현 범위

- React/Vite 앱 진입점, 반응형 화면, 얼굴 스캔 후 정면 5구역의 손으로 펴 바르는 동작 관찰과 실제 좌표 오버레이. 움직임 시간·이동 범위에 따라 구역별·전체 동작 진행률이 점차 올라갑니다.
- 5구역 동작 진행률이 모두 100%가 되면 완료 시각을 한 번 자동 기록하고 그 시각부터 UV별 재도포 알림을 켭니다. 직접 시각 입력과 기록 취소도 지원하며, 타임라인에 자동·직접 기록 출처를 표시합니다.
- 얼굴 메시의 각 관찰 부위는 진행률에 따라 아래부터 초록색으로 채워집니다. 부분 진행도 유지하고, 전체 완료 후에는 마지막 영상과 결과를 고정해 보여 줍니다. 새 도포를 시작하면 영상 재생과 진행률을 초기화합니다.
- 최신 UV와 이후 시간대 예보를 반영해 앞으로 바를 시각을 표시합니다. 시간이 이미 지났다면 지금 바르도록 안내하고 지금 바른다는 기준으로 이후 계획을 계산합니다. 기록과 예정은 구분하며 지난 예정을 자동 완료하지 않습니다.
- 하루 도포 타임라인은 도포 완료·현재 시각·앞으로 바를 시각·오늘 종료를 선과 점으로 이어 표시합니다. 완료는 초록 점, 현재와 다음 도포는 강조 점, 이후 예정은 빈 점으로 구분합니다.
- 기상청 UV 값에 요청된 구간표를 적용합니다: 0–2 알림 대기, 3은 150분, 4–5는 120분, 6–7은 80분, 8 이상은 60분. 개인 보호 시간을 측정하는 공식이 아닌 앱의 알림 정책입니다.
- 위치 동의 시 현재 위치와 동작 완료·알림마다 새 위치를 요청합니다. 마지막 확인 위치의 예보는 화면이 보이는 동안 30분마다 갱신하며, 값이 바뀌면 알림과 이후 계획을 다시 계산합니다. 현재 연결 데이터는 기상청 3시간 구간 예보입니다.
- UV를 확인할 수 없거나 조회 후 1시간이 지난 경우 기본 120분으로 계산합니다. 낮은 UV와 데이터 없음은 구분합니다.
- 알림은 페이지가 보일 때 확인하며, 절전·잠금·탭 전환 후 복귀하면 지난 알림을 한 번 처리합니다. 페이지를 닫은 상태의 예약 푸시는 지원하지 않습니다. 매일 동작 완료 또는 알림 버튼으로 켜며, 사용자가 설정한 종료 시각 이후에는 보내지 않습니다.
- 기기 알림 권한이 없어도 화면 알림을 표시합니다. 위치·예보 실패도 기록 기준 알림을 막지 않습니다.
- 얼굴·손 동작 인식 베이스라인을 연결했습니다. 실제 선크림 존재·접촉·도포량·차단력은 판정하지 않습니다.
- 내 선크림 등록: 제품 라벨 사진(앞면·뒷면)을 사용자 동의 후 Gemini로 읽어 후보를 제시하고, 제품명·SPF·PA·제형이 모두 읽히면 바로 등록합니다. 읽지 못한 항목만 직접 입력하며 등록 후 수정할 수 있습니다. 표기된 SPF·PA를 활동 환경별 일반 가이드와 비교한 안내와 SPF·PA 설명을 함께 보여 줍니다. 아래 "제품 라벨 인식"을 참고하세요.
- [얼굴 사용량 실험 가이드](/face-dose.html)에서 MediaPipe 홍채 기준 부분 얼굴 면적과 손가락 줄 길이 참고값을 확인할 수 있습니다. 이는 얼굴 전체 권장량이 아니며, 10mL 비매품 용기의 토출량은 미실측입니다.
- 데모 데이터, 터치 시연, UV 슬라이더, 샘플 성분, 임의 도포율 및 보호 시간 계산을 포함하지 않습니다.
- 영상·특징점은 브라우저 메모리에서만 분석하며 저장·외부 전송하지 않습니다. 도포 기록은 최근 30일분을 localStorage에 보관하고 페이지 진입 시 정리합니다. 위치와 예보는 메모리에서만 사용합니다.

## 기상청 UV 연결

기록·타임라인·알림은 API 키 없이도 사용할 수 있습니다. 실제 UV 예보는 [기상청 생활기상지수 조회서비스(4.0)](https://www.data.go.kr/data/15085288/openapi.do)에 활용 신청한 공공데이터포털의 일반 인증키(Decoding)가 필요합니다.

`.env`가 없을 때 `.env.example`을 복사하고 `KMA_SERVICE_KEY`를 입력한 뒤 서버를 재시작하세요. 키는 서버에서만 읽으며 `VITE_` 환경 변수로 넣지 않습니다. 기존 `.env`를 덮어쓰지 마세요.

`GET /api/uv?latitude=37.567&longitude=126.978`은 인근 공식 지점·발표 시각·구간별 예보를 반환합니다. 키가 없으면 503, 잘못된 위치는 400, 예보 조회 실패는 502를 반환합니다. 가상 수치를 대신 표시하지 않습니다.

위치 동의 전에는 좌표를 요청하지 않습니다. 동의 후 약 0.001도 단위 좌표를 앱 서버에 보내고, 기상청에는 인근 지점 코드만 보냅니다. 앱은 좌표를 저장하거나 로그로 남기지 않습니다. 배포 시 프록시의 요청 URL 로그에서도 좌표를 제외해야 합니다. 데이터 흐름·근거·한계는 [기능 설계](docs/superpowers/specs/2026-11-14-reapplication.md)에 정리했습니다.

## 제품 라벨 인식

제품 사진 분석은 서버의 `POST /api/recognize`가 Google Gemini에 전달합니다. 키는 `.env`의 `GEMINI_API_KEY`에 두며 브라우저로 내려가지 않습니다. 키가 없으면 503을 돌려주고 화면은 직접 입력으로 안내합니다. 기본 모델은 `gemini-3.8-flash`이고 혼잡(503/429)·시간 초과 시 `gemini-3.5-flash-lite`로 한 번 재시도합니다. `GEMINI_MODEL`, `GEMINI_FALLBACK_MODEL`로 바꿀 수 있습니다.

- 브라우저에서 긴 변 1280px JPEG로 줄인 사진만 전송하며 사진 2장, 장당 2MB, 요청 6MB를 넘으면 거절합니다. 서버는 사진을 저장하거나 로그에 남기지 않습니다. 얼굴 카메라 영상은 이 경로를 거치지 않습니다.
- 모델 응답은 서버에서 다시 검증합니다(SPF 15~100, PA 1~4, 제형·내수성 enum, 성분 200개 제한). 모델이 읽지 못한 값은 null로 남기며 전형적인 값으로 채우지 않습니다.
- 재도포 안내는 SPF와 무관하게 일반 권고 120분을 쓰고, 내수성은 라벨의 40/80분 표기만 전달합니다. 활동 환경 안내는 소비자 가이드 표와의 비교이며 보호 시간을 계산하지 않습니다.
- 데이터 흐름·보관 정책·동의 문구는 [제품 사진 데이터 흐름](docs/sunguard/05-product-photo-data-flow.md), 설계는 [제품 등록·사진 인식·맞춤 솔루션](docs/superpowers/specs/product-profile.md)에 있습니다.
- Tailscale로 노출해 휴대폰에서 시험할 때는 `tailscale serve --bg 5173`을 쓰며, `*.ts.net` 호스트는 Vite 설정에서 허용돼 있습니다.

## 현재 지역 자외선지수 (생활안전지도)

기존 **현재 위치와 자외선 예보** 영역에서 위치 전달 동의 후 **현재 위치 기반 UV 조회**를 누릅니다. 새 기능은 VWorld로 시도·시군구를 확인하고, 행정안전부 생활안전지도의 지역 자료에서 자외선지수와 실제 발생시각을 표시합니다. 기상청 `/api/uv`, `forecast.slots`, 도포 기록, 재도포 알림 계산에는 값을 넣지 않습니다. 생활안전지도 자료도 기상청 정보를 정리한 것으로, 이 화면의 값을 현장 실측이라고 표현하지 않습니다.

프로젝트 루트(이 README와 `package.json`이 있는 폴더)의 서버 전용 `.env`에 다음 두 줄을 추가한 뒤 서버를 재시작합니다. `.env`가 없으면 `.env.example`을 복사하되 기존 `.env`와 `KMA_SERVICE_KEY`를 덮어쓰지 마세요.

```dotenv
SAFEMAP_SERVICE_KEY=생활안전지도에서_발급받은_실제_인증키
VWORLD_API_KEY=VWorld에서_발급받은_실제_인증키
```

실제 키를 `VITE_` 변수나 프론트엔드 코드에 넣거나 Git에 올리지 마세요. 빈 값 또는 `[자외선 인증키]`, `[지역명 인증키]` 같은 대괄호 플레이스홀더이면 서버는 외부 API를 호출하지 않고 503 설정 안내를 반환합니다. 신규 API는 `GET /api/uv/current?latitude=...&longitude=...`입니다. 인증 실패, 위치 미지원, 지역 조회 실패, 일치 자료 없음, 통신·시간 초과, 응답 형식 오류를 별도 코드로 반환합니다.

위치는 이 조회의 별도 체크박스에 동의한 뒤 버튼을 누를 때만 확인합니다. 약 0.001도 단위 좌표를 앱 서버와 VWorld에 전달하며 저장·로그에 남기지 않습니다. 생활안전지도에는 좌표나 지역 필터 없이 문서에 있는 네 파라미터만 보냅니다. 동의를 해제하면 화면의 결과도 지웁니다. 배포 프록시·모니터링에서도 이 경로의 쿼리 문자열(좌표)을 로그에 남기지 않도록 설정하세요.

각 외부 호출은 최대 8초, 서버의 전체 조회는 최대 25초입니다. 한 페이지 1,000건을 요청하되 실제 응답의 `numOfRows`, `pageNo`, `totalCount`와 받은 건수를 확인하며 최대 100페이지를 순차 조회합니다. 전체 조회가 완료되어야 최신 값을 확정하며 중간 실패 시 부분 결과를 반환하지 않습니다. 시도는 명시적인 정식 명칭·약칭 목록으로, 시군구는 공백을 제외한 정확 일치로 매칭합니다. 일반구는 `level3`가 명시적인 구일 때만 합칩니다. 다른 구·인근 지역으로 대체하지 않으며 값 0도 유효합니다.

발생시각은 한국 시간으로 해석하며 유효하지 않은 날짜·결측값·5분 이상 미래 자료를 제외합니다. 일치 지역 중 유효한 발생시각이 가장 늦은 자료를 고릅니다. **6시간 초과 자료를 오래됨으로 표시하는 것은 앱의 보수적인 표시 기준이며, 제공기관이 보장한 갱신주기가 아닙니다.** 화면이 열린 뒤에도 이 기준에 도달하면 경고합니다.

공식 명세: [생활안전지도 자외선지수 IF_0113](https://www.safemap.go.kr/opna/data/dataViewRenew.do?objtId=232), [VWorld 주소 API](https://www.vworld.kr/dev/v4dv_geocoding2_s001.do). 생활안전지도 문서의 요청 파라미터·출력 필드·발생시각 예시는 확인했지만, 실제 키가 없어 인증된 JSON 응답·최대 페이지 크기·지역별 자료 유무·최신성은 검증하지 못했습니다. 테스트는 **공식 필드명에 기반해 만든 모의 응답이며 실제 API 캡처가 아닙니다.** JSON 어댑터는 `response.header/body` 또는 `header/body`, 목록 `items.item`(배열/단건) 또는 `items` 배열을 지원하고, 알 수 없는 형식은 오류로 처리합니다. 운영 키를 넣은 뒤 응답 구조가 다르면 `server/safemap-uv.js`의 `parseSafemapPage`를 실제 응답에 맞춰 검증·조정해야 합니다. VWorld 결과 배열/단건과 시군구·일반구 표기도 실제 운영 지역에서 확인하세요.

`npm test`는 기존 기능과 신규 기능의 모의 API 테스트를 함께 실행합니다. `npm run build` 후 `npm run test:e2e`는 기존 Chrome 브라우저 테스트와 신규 동의·조회·권한 거부 흐름을 검사합니다.

### 기존 서버에 반영

이 작업은 로컬 소스 구현이며 `https://1.tail381297.ts.net/` 배포 완료를 의미하지 않습니다. 배포 담당자는 변경된 서버·프론트엔드 파일을 **함께** 반영하고 다음 순서로 확인하세요.

1. 기존 `.env`의 기상청 키를 유지하면서 위 두 키를 추가합니다. VWorld 키의 실제 배포 도메인 허용 설정과 생활안전지도 이용 승인을 확인합니다.
2. 기존과 동일하게 `npm ci`, `npm test`, `npm run build`를 실행합니다. 기존 프로세스를 배포 도구로 재시작하고 `npm start`(Express)로 빌드와 API를 함께 제공합니다. `vite preview`만 실행하면 API가 제공되지 않습니다.
3. HTTPS 프록시가 기존 `/api/uv`와 신규 `/api/uv/current`를 동일 Express 서버로 전달하는지 확인하고, 프록시 응답 제한을 서버 전체 조회 25초보다 길게 설정합니다. 두 외부 HTTPS API로의 연결도 허용해야 합니다.
4. 실제 휴대폰에서 동의 전 위치 요청 없음, 위치 허용/거부, 실제 지역 일치, UV 0, 한국 시간 기준시각·오래됨 경고를 확인합니다. 서버·프록시 로그에 키·좌표가 없는지 확인합니다.
5. 기상청 예보 조회, 도포 기록, 재도포 알림과 얼굴·손 동작 관찰이 유지되는지 확인합니다. 실제 응답을 공유할 때는 키·좌표를 제거하세요.

공유 조사 자료는 [문서 목차](docs/README.md)에서 확인할 수 있습니다.

## 얼굴 크기·사용량 실험 가이드

기본 도포 동작 화면의 **얼굴 크기·사용량 가이드** 버튼 또는 `/face-dose.html`에서 별도 안내를 엽니다. 얼굴 전체와 양쪽 홍채가 선명한 정면 사진을 촬영하거나 선택하면, 모델 영역·계산 질량·검지 마디 길이 기준 줄 길이를 보여줍니다. 손가락 마디 길이는 사용자가 참고값으로 조정할 수 있습니다.

홍채 지름 11.7mm 가정과 MediaPipe의 상대 깊이를 사용해 일부 삼각형 메시를 환산합니다. 눈과 입술 안쪽은 빼지만 이마 위·옆면·귀·목 등은 빠집니다. 2mg/cm²는 시험 도포량을 계산에 빌려온 기준입니다. 화면의 양을 해당 사용자나 제품의 권장량으로 읽으면 안 됩니다. 기본 5mm 줄 25mm당 0.5g도 제품 토출 측정값이 아닙니다. [계산 범위·오차 안내](docs/sunguard/06-face-dose-guide.md)를 확인하세요.

## 사용 순서

1. 카메라를 켜고 얼굴을 정면에 맞춥니다.
2. 이마·코·사용자 기준 왼쪽 볼·오른쪽 볼·턱의 표시를 확인합니다. 얼굴이 약 1초 안정되어야 시작할 수 있습니다.
3. **부위 확인 후 시작**을 누르고 손으로 펴 바릅니다.
4. 부위별 퍼센트와 전체 동작 진행률을 확인하며 바릅니다. **다시 시작**으로 초기화할 수 있습니다.
5. 5구역이 모두 100%이면 완료 시각이 **직전 도포 시각**과 타임라인에 기록되고 UV별 재도포 알림이 켜집니다. UV 0–2이면 대기하고, UV 연결 전에는 기본 120분을 적용합니다. 종료 시각이 지났으면 종료 시각을 조정하세요.
6. **새 도포 시작**으로 다음 관찰을 시작합니다. 카메라를 끄면 영상 트랙과 분석 자원을 해제하며, 저장된 시각은 유지됩니다.

얼굴 추적이나 자세 인식이 잠깐 끊기면 진행률을 보존하고 동작 계산을 멈춥니다. 2초 미만에 정상 얼굴이 돌아오면 자동으로 이어갑니다. 2초 이상 이탈, 두 개의 얼굴, 탭 숨김 또는 500ms를 넘는 영상 처리 공백이 있으면 부위를 다시 확인하고 시작 버튼을 눌러 이어갑니다. 이때도 같은 부위의 유효 동작 누적은 유지하며, 관찰하지 못한 시간과 중단 전후 위치 차이는 적립하지 않습니다. 얼굴 본인 인증을 하지는 않으므로 다른 사람이 사용할 때는 **다시 시작**을 눌러 초기화하세요.

## 관찰 방식과 한계

MediaPipe 얼굴 특징점으로 5구역을 정의하고, 손가락 여러 점이 부위 안에서 움직이는 시간·이동 범위를 확인합니다. 머리 움직임과 영상 종횡비를 보정하고 두 손의 시간을 합산하지 않습니다. 유효 움직임 시간 기준은 코 1초, 턱 1.5초, 이마·양 볼 각각 2초이며 실기기 보정이 필요합니다. 영상 위 표시와 거울 반전·cover 크롭은 같은 좌표 변환을 사용합니다.

구역별 퍼센트는 유효 움직임의 누적 시간·이동 거리 기준의 달성 비율 중 작은 값이며, 전체는 5구역의 동일 가중 평균입니다. 각 연속 관찰에서 최소 이동 범위를 확인한 뒤 움직이는 프레임만 누적합니다. 손이 잠시 사라지거나 다른 부위로 이동한 후 돌아와도 같은 부위의 누적을 이어갑니다. 기본 완료 기준은 코 1초, 턱 1.5초, 이마·양 볼 각각 2초의 유효 동작 누적과 최소 이동 거리 충족이며, 문지른 횟수를 세지는 않습니다. 얼굴 추적 손실 후 다시 스캔해도 누적은 유지하며, **다시 시작**·카메라 종료·새 관찰 시작 시 초기화합니다. 완료하면 분석 루프와 모델을 종료해 기록이 반복되지 않도록 합니다.

- 정지한 손·작은 좌표 떨림·짧은 통과·고개만 움직이는 경우를 합성 테스트로 구분합니다.
- 얼굴 앞 공중 문지르기, 빈손 문지르기, 보습제를 바르는 동작도 감지될 수 있습니다.
- 손·머리카락·수염·기울임·조명과 기기 성능에 따라 추적이 실패할 수 있습니다. 얼굴/손 모델은 피부나 접촉의 정답 분할기가 아닙니다.
- 눈가·귀·목과 가려진 부위는 이번 관찰 범위 밖입니다. 결과를 얼굴 전체 도포 완료나 도포율로 해석하지 않습니다.
- 스틱·쿠션·분사 자체의 동작 인식은 포함하지 않습니다. 해당 제품을 손으로 펴 바르는 동작은 제품 종류로 제외하지 않습니다.
- UV 정보와 재도포 알림은 위의 구현 범위대로 연결했습니다. 제품 등록의 성분 목록은 라벨 전사이며 개인별 자극·안전성을 판정하지 않습니다.

## 영상 처리와 모델 자산

영상·프레임·특징점은 브라우저 메모리에서만 처리하고 자동 저장하거나 서버에 전송하지 않습니다. 영상 분석은 백엔드·외부 이미지 분석 API·API 키를 사용하지 않습니다. 기상청 UV API는 별도의 서버 기능입니다. 세션 종료 시 메모리 참조와 카메라/모델 자원을 정리합니다.

`@mediapipe/tasks-vision` **0.10.32**와 공식 float16/1 얼굴·손 모델을 고정합니다. `npm run dev`와 `npm run build`는 먼저 `npm run prepare:vision`을 실행합니다.

- 첫 준비에는 npm 및 Google 모델 배포 호스트(`storage.googleapis.com`)에 연결할 네트워크가 필요합니다. 이는 소프트웨어 자산 다운로드이며 카메라 영상 업로드가 아닙니다.
- `scripts/vision-assets.json`의 고정 URL·SHA-256으로 모델 두 개를 확인하고, 설치된 패키지의 WASM을 `public/vision/`에 복사합니다.
- 검증된 캐시는 재사용합니다. 실패하면 연결 상태를 확인하고 `npm run prepare:vision`으로 재시도합니다.
- 생성 자산은 Git에서 제외합니다. 빌드에는 자산과 라이선스 고지가 포함되며, 실행 중에는 앱과 같은 출처의 `/vision/`에서 제공합니다.
- SDK 업그레이드 시 외부 통계 전송 여부를 다시 확인해야 합니다. 1.2.3에서는 자동 Google metrics 요청이 관찰되어 0.10.32로 고정했습니다.

라이선스와 출처는 [제3자 고지](THIRD_PARTY_NOTICES.md)에 기록합니다.
